# 商品管理分类树主从布局设计

状态：方案已确认，原型已实施

## 1. 目标与范围

商品管理页面采用左侧分类树、右侧商品列表的主从布局，使运营人员能够先定位平台分类，再查看和筛选对应商品。

本页面只展示自营商品和已经归集进入平台商品库的集采商品；未映射、未归集的上游原始商品在供货平台内处理，不进入商品管理。

## 2. 页面结构

### 2.1 页面顶部

- 保留内容页左上角灰色提示词。
- 保留“平台兜底加价”“新建自营商品”等页面级操作入口。
- 不增加重复的大标题或说明卡片。

### 2.2 左侧分类树

- 左侧分类区固定宽度约 240px，右侧商品区占据剩余空间。
- 分类树顶部固定展示“全部”节点。
- “全部”节点下展示平台一级分类和二级分类，复用分类管理中的两级分类数据。
- 页面初始化时默认选中“全部”。
- 一级分类的展开箭头和分类名称使用独立点击区域：
  - 点击箭头只展开或收起二级分类，不触发商品查询。
  - 点击分类名称选中分类，并触发右侧商品查询。
- 当前节点必须具有明确的选中态；分类切换后页码回到第 1 页。

### 2.3 右侧商品列表

- 商品查询表单移动到右侧顶部。
- 查询表单继续遵循统一查询列表规范，只包含查询字段、“查询”和“重置”。
- 查询表单中展示只读的当前分类信息，格式为“当前分类：分类名称”。
- 查询表单提供商品来源普通下拉框，选项为全部来源、自营商品、集采商品，不增加来源页签。
- 商品表格和分页位于查询表单下方，不展示重复的表格标题、记录数或刷新栏。
- 商品列表字段、行内操作及页面级操作沿用现有商品管理定义。

## 3. 分类查询规则

| 选中节点 | 查询范围 |
| --- | --- |
| 全部 | 不附加分类条件，查询全部商品 |
| 一级分类 | 查询该一级分类及其全部二级分类下的商品 |
| 二级分类 | 只查询该二级分类直属商品 |

分类树是商品浏览范围，不是右侧临时查询表单字段。点击“重置”时清空商品关键字，将商品来源恢复为“全部来源”、商品状态恢复默认值，保留当前分类选择，并从第 1 页刷新该分类下的商品列表。

## 4. 状态与触发关系

| 触发动作 | 左侧分类状态 | 右侧查询状态 | 右侧列表 |
| --- | --- | --- | --- |
| 首次进入页面 | 选中“全部” | 使用默认空条件 | 查询全部商品第 1 页 |
| 点击一级分类名称 | 选中该一级分类 | 当前分类同步更新 | 查询一级及其全部二级分类商品第 1 页 |
| 点击二级分类名称 | 选中该二级分类 | 当前分类同步更新 | 查询该二级分类直属商品第 1 页 |
| 点击一级分类箭头 | 选择不变 | 条件不变 | 列表不刷新 |
| 点击查询 | 选择不变 | 使用当前表单条件 | 在当前分类范围内查询第 1 页 |
| 点击重置 | 选择不变 | 清空临时查询字段 | 在当前分类范围内查询第 1 页 |
| 点击分页 | 选择不变 | 条件不变 | 查询当前条件指定页 |

## 5. 数据与接口约束

- 分类树复用平台分类数据，不复制或单独维护商品管理专用分类。
- 商品查询统一传递 `categoryId` 与 `categoryScope`：
  - 全部：`categoryId` 为空，`categoryScope=ALL`。
  - 一级分类：传一级分类 ID，`categoryScope=WITH_DESCENDANTS`。
  - 二级分类：传二级分类 ID，`categoryScope=DIRECT`。
- 当前原型使用前端静态数据模拟上述参数和筛选行为；后续真实接口沿用相同查询语义。
- 分类无数据时仍展示“全部”节点，右侧商品查询不受影响。
- 分类加载失败时不得使用残留分类 ID 查询；回退到“全部”并提示分类加载失败。

## 6. 验收标准

1. 商品管理页面呈现左侧分类树和右侧商品列表，不再是单列通用列表布局。
2. 左侧固定存在“全部”节点，首次进入默认选中。
3. 一级和二级分类均可被选中，右侧同步显示当前分类名称。
4. 选择一级分类时按包含下级的口径查询，选择二级分类时按直属口径查询。
5. 点击展开箭头不改变分类选择，也不刷新商品列表。
6. 分类切换、查询和重置后页码均回到第 1 页。
7. 重置清空关键字、恢复全部来源和默认状态，但保留左侧分类选择。
8. 页面继续满足查询表单和表格区的统一规范。
9. 原有商品列表字段、分页以及页面级操作入口保持可用。
10. 商品来源使用普通下拉框；商品管理不出现未映射、未归集来源商品，也不新增小程序或 API 商品展示开关。
