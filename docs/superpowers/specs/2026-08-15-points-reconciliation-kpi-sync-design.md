# 积分对账 KPI 同步设计

- 日期：2026-08-15
- 状态：已实现并通过静态与浏览器回归
- 适用范围：拾马商城平台运营后台一期静态原型
- 覆盖端：Web 平台运营后台；小程序和客户 API 不增加入口

## 1. 业务目标

将 API 供货侧“资金对账”的月度概览能力同步到小程序商城侧，使运营人员进入积分页面后即可同时掌握月度积分流量、当前积分存量与未闭环差异；并将“积分账户”统一更名为“积分对账”，让菜单名称与页面用途一致。

成功标准：运营人员在同一屏内能够回答“本月充值和消费了多少积分”“当前可用和冻结积分是多少”“本月产生了多少积分差异”“还有多少订单待核对”。

## 2. 用户故事

| 用户 | 需求 | 价值 |
|---|---|---|
| 商城运营 | 进入积分对账页后先查看本月积分关键指标 | 快速判断积分规模和账户健康度 |
| 财务复核人员 | 同时比较积分流入、流出和当前存量 | 无需逐企业汇总账户明细 |
| 异常处理人员 | 查看积分差异与待核对订单 | 优先处理尚未闭环的问题 |

## 3. 范围与优先级

| 范围 | 优先级 | 成本 | 说明 |
|---|---|---:|---|
| “积分账户”更名为“积分对账” | MVP | S | 同步侧边栏、页面标题、角色菜单展示和 PRD 文案 |
| 顶部六项 KPI 看板 | MVP | S | 复用资金对账看板的视觉结构和响应式规则 |
| 保留企业积分账户明细 | MVP | S | 不改现有查询、登记充值、表格和分页流程 |
| KPI 下钻、趋势和自定义周期 | 延后 | M | 一期不增加未定义的数据交互 |
| 真实积分账务接口与自动刷新 | 延后 | L | 静态原型不模拟后端账务执行 |

商城订单已与 API 订单共用状态快捷页签、操作栏、动态按钮和处理弹窗，本次只做回归确认，不重复实现，也不增加权限逻辑。

## 4. 页面结构

积分对账页从上到下为：

1. 页面说明及“登记积分充值”操作。
2. 六项关键 KPI 看板。
3. 原查询表单。
4. 原企业积分账户明细表格与分页。

查询表单只筛选下方企业账户明细，不改变顶部全局 KPI。

## 5. KPI 定义

| KPI | 单位 | 统计口径 | 辅助信息 |
|---|---|---|---|
| 本月积分充值 | 积分 | 当前自然月已入账充值积分之和 | 本月充值企业数或充值笔数 |
| 本月积分消费 | 积分 | 当前自然月已完成扣减的消费积分之和 | 已完成扣减订单数 |
| 当前可用积分 | 积分 | 当前数据范围内企业可用积分汇总快照 | 当前账户数量与更新时间 |
| 当前冻结积分 | 积分 | 当前仍处于冻结状态的积分汇总快照 | 对应处理中订单数 |
| 本月累计差异 | 积分 | 本月新增且已确认的积分差异事件绝对值之和 | 当前未解决差异数量 |
| 待核对订单 | 笔 | 当前尚未完成积分冻结、扣减或退回归因的订单数 | 最长待处理时长 |

## 6. 数据与边界规则

- 充值、消费和累计差异按当前自然月累计；月初自动切换新周期。
- 可用积分和冻结积分为当前存量快照，不按月累计。
- 差异来源包括订单应冻结、应扣减或应退回积分与账户流水实际结果不一致。
- 同一未解决差异在重复核对中只累计一次；已解决差异不冲减本月累计值，当前未解决数量由辅助信息表达。
- 待核对订单不受月份边界限制，跨月未解决订单继续保留。
- 月度业务为空时显示 `0 积分`；数据尚未获取时显示“暂未获取”，不得将缺失值按零计入。
- 指标仅汇总当前数据范围内的小程序商城客户，不混入 API 客户人民币资金数据。
- 本次只调整菜单文案，内部视图代码继续使用 `points-accounts`，避免破坏现有导航和状态。

## 7. 视觉与交互

- 复用资金对账 KPI 卡片的尺寸、间距、字体和风险色体系。
- 1440px 下六项单行展示；1024px 下每行三项，页面不得产生横向滚动。
- 充值、消费和可用积分使用品牌蓝或绿色；冻结积分使用橙色；累计差异和待核对订单使用红色。
- 指标名称、主值和辅助说明独立表达含义，颜色不作为唯一信息来源。
- KPI 卡片一期只读，不增加点击下钻、筛选联动、趋势图或独立周期选择器。

## 8. 异常场景

| 场景 | 展示规则 |
|---|---|
| 本月无充值或消费 | 对应月累计指标显示 `0 积分` |
| 部分账户快照缺失 | 汇总已获取账户，并在辅助信息中明确覆盖范围 |
| 全部账户快照缺失 | 当前存量指标显示“暂未获取” |
| 同一差异被多次发现 | 只按首次确认事件累计一次 |
| 待核对订单跨月未关闭 | 继续计入待核对订单 |
| 查询某一家企业 | 只过滤下方明细，顶部 KPI 保持全局口径 |

## 9. 验收标准

- 侧边栏、页面标题、角色菜单展示和 PRD 中的功能名称统一为“积分对账”。
- 页面说明与查询表单之间恰好展示一个积分对账 KPI 看板。
- 看板完整展示六项指标、主值和辅助信息。
- 月累计指标与当前快照在文案中有明确区分。
- 查询、重置、登记积分充值、账户明细和分页流程保持可用。
- 1440px 下六卡单行，1024px 下三卡两行且无页面级横向滚动。
- 商城订单与 API 订单现有操作栏回归继续通过。
- 不新增或调整角色、菜单、按钮权限逻辑。
