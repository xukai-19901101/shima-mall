# 分类映射需求与操作流程设计

- 日期：2026-08-14
- 状态：方案与静态原型 UI 已实施并通过回归验证
- 适用范围：拾马商城平台后台一期“供货平台管理 / 分类映射”

## 1. 业务目标

平台自建一套两级商品分类，多个供货平台分别提供各自的两级来源分类。分类映射用于把来源二级分类唯一关联到平台二级分类，使集采商品能够动态解析平台分类并进入商品管理、企业开放分类和分类加价规则。

一期目标：

- 平台运营可以按供货平台查看全部来源二级分类及其映射结果。
- 个别分类通过页面手工设置、修改或解除映射。
- 批量调整全部通过当前供货平台页签内的增量导入完成。
- 未映射商品有明确查看入口，并可从分类映射页跳转定位。
- 修改映射只更新映射关系，不迁移或批量更新集采商品表。
- 所有手工和导入变更可审计、可追溯。

成功标准：

- 一个来源二级分类最多存在一个当前有效目标分类。
- 一个平台二级分类可以关联多个来源二级分类。
- 页面中不存在无业务来源的“待确认”或可长期保存的“冲突”状态。
- 解除映射后，相关商品立即退出商品管理和下游可售范围，并可在来源商品待映射视图中找到。

## 2. 用户故事

| 使用者 | 用户故事 |
|---|---|
| 平台运营 | 切换供货平台后快速定位未映射来源分类，并逐条设置目标平台分类 |
| 平台运营 | 导出当前平台映射、批量编辑后增量导入，并在执行前看到影响和错误 |
| 平台运营 | 修改或解除映射前看到有效商品数，理解本次操作会影响分类展示、企业开放范围和分类加价 |
| 商品运营 | 从未映射分类的商品数量进入来源商品页，查看具体未映射商品 |
| 审计人员 | 查看某条映射的历次新增、修改、解除和恢复记录 |

## 3. 核心对象与关系

### 3.1 分类层级

- 平台分类固定为两级。
- 供货平台来源分类固定为两级。
- 只对来源二级分类建立映射。
- 来源一级分类只用于树形路径、分组和查询，不保存映射。
- 目标必须是启用中的平台二级分类；平台一级分类由目标二级分类自动反推。

### 3.2 映射基数

```text
一个平台二级分类 ← 多个来源二级分类
一个来源二级分类 → 最多一个平台二级分类
```

来源分类唯一身份必须同时包含供货平台：

```text
(supplier_id, source_level2_category_id)
```

不同供货平台可以使用相同来源分类 ID 或名称，不得仅凭分类名称建立关联。

### 3.3 集采商品分类解析

集采商品表只保存来源分类 ID，不冗余保存平台分类：

```text
集采商品.source_category_id
→ 当前供货平台的有效映射
→ 平台二级分类
```

自营商品仍直接保存平台二级分类 ID，不经过来源分类映射。

修改映射时只更新映射关系表、审计日志和映射版本，不迁移集采商品表。商品管理、分类统计、企业开放分类和分类加价在新请求中动态读取最新映射。

## 4. 当前数据文件判断

现有 `ys_category_mapping.sql` 只有以下字段：

```text
id
pid
level
cname
```

该文件表达的是一套两级分类树数据，不包含供货平台、来源分类和目标平台分类之间的关联字段，因此不能直接作为分类映射关系表使用。

实施时需要先确认该表实际归属：

- 如果它是平台标准分类，则迁入或关联平台分类表。
- 如果它是某个供货平台来源分类，则补充明确的 `supplier_id` 后迁入来源分类表。
- 无论属于哪一种，都必须新增独立映射关系表，不能把分类节点表同时当作映射关系表。

此判断不要求一期立即重命名存量表，但接口和领域模型中必须区分“分类节点”和“分类映射”。

## 5. 页面信息架构

### 5.1 页面结构

分类映射页面使用“供货平台页签 + 查询表单 + 映射表格”，替换现有左右双树映射工作台。

```text
灰色页面说明                    导入记录｜导出映射｜导入映射

[京选集采 未映射26] [企采云 未映射18] [华采供应链 未映射42]

来源分类名称/编码｜映射状态｜来源状态｜查询｜重置

来源分类编码｜来源分类路径｜有效商品数｜目标平台分类
映射状态｜来源状态｜更新时间｜操作
```

页面继续遵循后台查询列表统一规范：

- 保留内容区左上角灰色说明词。
- 查询表单只包含查询字段、查询和重置。
- 导入记录、导出映射、导入映射属于页面级业务操作，放在说明区右侧。
- 表格上方不增加重复标题、刷新条或批量操作栏。
- 不提供页面多选框、批量映射按钮或统一保存按钮。

### 5.2 供货平台页签

- 每个已接入供货平台对应一个页签。
- 页签展示平台名称和未映射来源二级分类数量。
- 切换页签后，查询条件恢复默认值并查询该平台第 1 页。
- 页面手工操作和导入、导出都只能作用于当前页签平台。
- 不允许在一个页面操作中跨供货平台选择来源分类。

### 5.3 查询条件

| 字段 | 选项或规则 |
|---|---|
| 来源分类 | 按来源二级分类名称、编码或完整路径模糊查询 |
| 映射状态 | 全部、未映射、已映射 |
| 来源状态 | 全部、有效、已失效 |

映射状态只有未映射和已映射。“来源分类已失效”属于来源数据状态，不是第三种映射状态。

### 5.4 列表字段与操作

| 字段 | 说明 |
|---|---|
| 来源分类编码 | 当前供货平台的来源二级分类 ID 或编码 |
| 来源分类路径 | 来源一级分类 / 来源二级分类 |
| 有效商品数 | 当前分类下有效来源商品数，可点击跳转 |
| 目标平台分类 | 平台一级分类 / 平台二级分类；无映射显示未设置 |
| 映射状态 | 已映射或未映射 |
| 来源状态 | 有效或已失效 |
| 更新时间 | 最近一次映射关系变更时间 |
| 操作 | 设置映射、修改映射、查看历史 |

有效商品数跳转到“供货平台 / 来源商品”，自动带入：

- 当前供货平台。
- 当前来源二级分类。
- 当前映射或归集状态。

来源分类已失效时允许查看历史和解除原映射，不允许新建或修改为新的映射。

## 6. 单条手工操作

### 6.1 设置或修改映射

点击“设置映射”或“修改映射”打开弹窗。

只读信息：

- 供货平台。
- 来源一级分类和来源二级分类。
- 来源分类编码。
- 有效商品数。
- 当前目标平台分类。

可编辑信息：

- 平台一级分类。
- 平台二级分类。

最终必须选择启用中的平台二级分类。平台一级分类只用于缩小二级分类选项，不能单独保存。

修改前展示：

- 原目标分类和新目标分类。
- 受影响有效商品数。
- “保存后将即时影响商品分类展示、企业开放分类和分类加价计算”的提示。

保存后：

1. 更新当前映射关系。
2. 写入审计日志。
3. 递增当前供货平台映射版本。
4. 相关缓存因版本变化失效。
5. 列表重新查询当前行。

不执行集采商品表迁移或批量更新。

### 6.2 解除映射

修改弹窗内提供“解除映射”，不要求来源分类下商品数为零。

二次确认需明确：

- 受影响的有效商品数量。
- 商品将退出商品管理和下游可售范围。
- 商品会进入来源商品待映射视图。
- 历史订单不受影响。

确认后删除当前映射关系、记录解除日志并递增映射版本。后续重新映射时，商品根据新关系自动重新进入商品分类解析。

### 6.3 并发控制

- 映射编辑弹窗加载当前关系的 `row_version`。
- 保存和解除时必须携带该版本。
- 版本不一致时返回 `MAPPING_VERSION_CONFLICT`，不覆盖他人操作。
- 页面提示“该映射已被其他操作修改，请刷新后重试”。

## 7. 导入与导出

### 7.1 导入范围

- 批量调整全部通过导入完成。
- 导入只处理当前供货平台页签。
- 不同供货平台必须分别切换页签、分别下载模板和导入。
- 导入采用增量语义，文件未出现的来源分类保持不变。
- 不使用全量覆盖，避免遗漏行导致意外解除映射。

### 7.2 导入字段

| 字段 | 必填 | 规则 |
|---|---|---|
| 供货平台编码 | 是 | 模板固定，必须与当前页签一致 |
| 来源二级分类 ID | 是 | 作为来源分类匹配键 |
| 来源分类路径 | 否 | 仅供人工核对，不作为匹配条件 |
| 操作类型 | 是 | 绑定或解除 |
| 平台二级分类编码 | 绑定必填 | 解除时留空 |
| 平台分类路径 | 否 | 仅供人工核对 |
| 备注 | 否 | 写入导入审计记录 |

分类名称和路径可能重名或变更，系统不能使用名称或路径作为唯一匹配键。

### 7.3 导入流程

```text
选择供货平台页签
→ 下载该平台模板或导出当前映射
→ 上传增量调整文件
→ 解析与校验
→ 展示预览统计和失败明细
→ 人工确认
→ 执行校验通过的行
→ 展示执行结果并下载失败明细
```

预览统计：

- 新增绑定数。
- 修改映射数。
- 解除映射数。
- 无变化数。
- 校验失败数。
- 受影响有效商品数。

预览结果绑定当前供货平台映射版本。预览后如果映射版本已变化，执行时拒绝整次任务并要求重新预览，避免运营确认内容与实际执行内容不一致。

### 7.4 校验与部分成功

- 文件中的供货平台编码必须全部等于当前页签平台，否则整个文件拒绝。
- 同一文件重复出现同一来源分类时，相关重复行全部失败，不采用最后一行覆盖。
- 来源分类必须属于当前供货平台。
- 有效来源分类可以绑定或解除；已失效来源分类只能解除原映射。
- 绑定目标必须是启用中的平台二级分类。
- 解除已经未映射的数据计入无变化。
- 已经满足目标关系的绑定计入无变化。
- 无变化行不重复写映射或审计日志。
- 执行前逐行重新校验，目标分类在预览后被停用时该行失败。
- 合法行分别执行，单行失败不回滚其他成功行。
- 执行完成后统一递增一次当前供货平台映射版本。

失败明细包含行号、来源分类、目标分类、错误码和可读原因，并支持下载。

### 7.5 导出与导入记录

- “导出映射”导出当前供货平台、当前查询条件下的来源分类与映射结果。
- 导出文件可作为增量导入编辑底稿，但必须填写明确操作类型。
- “导入记录”展示任务编号、供货平台、文件名、操作人、预览时间、执行时间、成功数、失败数和状态。
- 导入记录可以下载原文件和失败明细。

## 8. 未映射商品查看闭环

未映射商品统一归属“供货平台 / 来源商品”，不新增独立菜单或重复商品表。

入口：

1. 供货平台列表中的“未映射分类数”可点击，进入该平台待映射来源商品视图。
2. 分类映射列表中的有效商品数可点击，进入当前来源分类商品视图。
3. 来源商品页面的归集状态筛选提供全部、待映射、待归集、已归集。

解除映射后：

- 相关商品无法解析平台分类。
- 商品退出商品管理和下游可售范围。
- 来源商品状态变为待映射。
- 重新建立映射后，商品自动进入待归集或已归集状态，无需修改商品表。

## 9. 数据结构

### 9.1 来源分类

```text
supplier_category
├── id
├── supplier_id
├── source_category_id
├── parent_source_category_id
├── level
├── name
├── source_status          ACTIVE / INVALID
├── synced_at
└── updated_at
```

唯一约束：

```text
UNIQUE(supplier_id, source_category_id)
```

### 9.2 当前映射关系

```text
supplier_category_mapping
├── id
├── supplier_id
├── source_level2_category_id
├── platform_level2_category_id
├── row_version
├── created_by
├── created_at
├── updated_by
└── updated_at
```

唯一约束：

```text
UNIQUE(supplier_id, source_level2_category_id)
```

映射表只保存当前关系。解除映射删除当前关系；历史由审计表保存。

### 9.3 映射审计日志

```text
supplier_category_mapping_audit
├── id
├── supplier_id
├── source_level2_category_id
├── operation_type        CREATE / UPDATE / UNBIND / RESTORE
├── before_platform_category_id
├── after_platform_category_id
├── operation_source      MANUAL / IMPORT / SOURCE_RESTORE
├── import_job_id
├── affected_product_count
├── operator_id
├── operated_at
└── correlation_id
```

### 9.4 导入任务

```text
category_mapping_import_job
├── id
├── supplier_id
├── file_name
├── file_hash
├── preview_mapping_version
├── status                PARSING / PREVIEW_READY / EXECUTING / PARTIAL_SUCCESS / SUCCESS / FAILED / EXPIRED
├── create_count
├── update_count
├── unbind_count
├── unchanged_count
├── failure_count
├── affected_product_count
├── operator_id
├── previewed_at
├── executed_at
└── created_at
```

任务行保存原始行号、解析字段、校验结果、执行结果和失败原因。

### 9.5 映射版本

每个供货平台维护单调递增的 `category_mapping_version`。分类解析和相关缓存键必须包含该版本：

```text
supplier_id + category_mapping_version
```

映射变更后递增版本，新请求不能继续命中旧映射缓存。缓存清理消息失败也不会导致旧缓存继续作为当前版本使用。

## 10. 数据与状态流转

| 触发事件 | 映射结果 | 商品结果 |
|---|---|---|
| 同步新增来源二级分类 | 未映射 | 进入来源商品待映射视图 |
| 新建映射 | 已映射 | 自动进入平台分类解析 |
| 修改目标分类 | 已映射 | 新请求即时按新目标分类展示和计算 |
| 解除映射 | 未映射 | 退出商品管理和下游可售范围 |
| 来源分类改名或更换一级父节点 | 映射不变 | 只更新来源分类路径 |
| 来源分类被删除或停用 | 映射记录保留但不参与解析 | 商品退出商品管理和下游 |
| 来源分类以同一 ID 恢复 | 原映射恢复生效并记日志 | 商品自动重新进入分类解析 |
| 平台目标分类停用 | 映射保留并标记目标已停用 | 商品停止进入下游可售范围 |
| 平台分类存在映射时尝试删除 | 阻止删除 | 提供查看关联映射入口 |

历史订单继续读取下单时的分类、定价和企业规则快照，不因当前映射变化而回写。

## 11. 接口设计

```http
GET    /admin/category-mappings
PUT    /admin/category-mappings/{source_category_id}
DELETE /admin/category-mappings/{source_category_id}
GET    /admin/category-mappings/{source_category_id}/history

POST   /admin/category-mapping-imports/preview
POST   /admin/category-mapping-imports/{job_id}/execute
GET    /admin/category-mapping-imports
GET    /admin/category-mapping-imports/{job_id}
GET    /admin/category-mapping-imports/{job_id}/failures
GET    /admin/category-mappings/export
```

列表接口必传 `supplier_id`，支持 `keyword`、`mapping_status`、`source_status`、分页和排序。

手工修改接口携带：

- 当前关系的 `row_version`；新建映射时为空。
- 目标平台二级分类 ID。
- 请求幂等键。

解除接口同样携带当前关系的 `row_version` 和幂等键。重复请求返回首次结果，不重复生成审计日志。

## 12. 状态与错误码

### 12.1 映射状态

```text
UNMAPPED
→ MAPPED
→ UNMAPPED
```

“冲突”是写入校验错误，不是映射状态；“待确认”不在一期范围。

### 12.2 错误码

| 错误码 | 场景 |
|---|---|
| `SUPPLIER_TAB_MISMATCH` | 导入文件供货平台与当前页签不一致 |
| `SOURCE_CATEGORY_NOT_FOUND` | 来源分类不存在或不属于当前平台 |
| `SOURCE_CATEGORY_INVALID` | 已失效来源分类尝试新增或修改映射 |
| `TARGET_CATEGORY_NOT_FOUND` | 目标平台二级分类不存在 |
| `TARGET_CATEGORY_DISABLED` | 目标平台分类已停用 |
| `MAPPING_VERSION_CONFLICT` | 并发修改导致版本不一致 |
| `IMPORT_DUPLICATE_SOURCE` | 文件内同一来源分类重复 |
| `IMPORT_PREVIEW_EXPIRED` | 预览后供货平台映射版本已变化 |
| `MAPPING_ALREADY_UNBOUND` | 解除对象已经未映射；导入中计为无变化 |

数据库唯一约束保证冲突关系不能持久化。并发保存发生唯一键或版本冲突时，接口返回明确错误并要求刷新，不生成“冲突数据”。

## 13. 异常与边界

| 场景 | 处理 |
|---|---|
| 两名运营同时修改一条映射 | 后提交者版本冲突，不能覆盖先提交结果 |
| 文件内同一来源分类对应两个目标 | 重复行全部失败 |
| 文件上传到错误供货平台页签 | 整个文件拒绝 |
| 预览后发生其他映射变更 | 预览失效，必须重新预览 |
| 预览后目标分类被停用 | 执行时该行失败，其他合法行继续 |
| 映射修改与解除重复请求 | 幂等返回首次结果，不重复写日志 |
| 映射写入成功但缓存通知失败 | 映射版本已变化，新请求不读取旧版本缓存 |
| 大量商品受影响 | 只更新映射和缓存版本，不批量更新商品表 |
| 分类名称重名 | 使用供货平台和来源分类 ID，不以名称匹配 |
| 来源分类恢复时目标平台分类已停用 | 映射记录恢复可见但不参与下游可售范围 |
| 导入部分行失败 | 成功行保留，失败行可下载和再次修正导入 |

## 14. 一期范围与开发量级

| 功能 | 优先级 | 量级 |
|---|---|---|
| 供货平台页签、查询列表和单条映射弹窗 | MVP 必做 | M |
| 解除映射、动态分类解析和缓存版本 | MVP 必做 | M |
| 增量导入预览、部分成功和失败明细 | MVP 必做 | L |
| 映射审计历史和导入记录 | MVP 必做 | M |
| 来源商品待映射跳转闭环 | MVP 必做 | S |
| 自动匹配推荐、页面多选批量映射 | 一期不做 | M |
| 映射历史一键回滚 | 一期不做 | M |

一期不做：

- 来源一级分类映射。
- 页面多选或拖拽批量映射。
- 自动分类匹配和待确认队列。
- 持久化冲突状态或冲突列表。
- 跨供货平台单次导入。
- 因映射变更而迁移集采商品表。

## 15. 验收标准

1. 不同供货平台通过页签切换，页面和导入任务均保持单平台上下文。
2. 只对来源二级分类映射，来源一级分类不保存映射。
3. 一个来源二级分类最多映射到一个平台二级分类，一个平台二级分类可关联多个来源分类。
4. 页面使用查询表格，不再出现左右双树、待确认、冲突、页面多选、批量映射或保存映射入口。
5. 未映射行可设置映射，已映射行可修改、解除和查看历史。
6. 修改或解除映射只更新映射关系、审计日志和映射版本，不批量更新集采商品表。
7. 解除映射后相关商品退出商品管理和下游，并进入来源商品待映射视图。
8. 未映射商品可以从供货平台未映射数量、分类映射商品数和来源商品筛选三个入口定位。
9. 导入为当前供货平台的增量操作，支持预览、人工确认、部分成功和失败明细下载。
10. 文件未出现的来源分类保持不变，重复来源分类行全部失败。
11. 手工和导入变更均记录前后值、操作人、时间、来源和受影响商品数。
12. 来源分类失效、恢复和平台目标分类停用时按本设计状态规则处理。
13. 映射变化后，新请求按新关系计算商品分类、企业开放范围和分类加价，历史订单快照不变。
14. 现有分类节点数据与映射关系数据在领域模型和数据库中明确分离。
