# 拾马商城分类管理树形表格设计

- 日期：2026-08-14
- 状态：统一新增入口方案已确认，原型已实施
- 适用范围：平台后台 `商品库 / 分类管理`

## 1. 目标

将现有“左侧分类树 + 右侧详情”的分类管理页面改为可展开的树形表格，使运营人员能在一个列表中查看两级分类层级、商品归集数量与分类状态，并通过统一新增入口创建一级或二级分类。

本次只调整平台分类管理页面，不改变两级分类数据模型，也不合并供货平台的“分类映射”功能。

## 2. 页面结构

页面由三个区域组成：

1. 左上角灰色说明词：说明平台分类为两级结构及数量统计口径。
2. 查询工具栏：只包含分类名称或编码搜索、分类层级筛选、状态筛选、查询和重置。
3. 树形表格：一级分类作为父行，展开后显示直属二级分类行。

页面继续使用顶部面包屑作为唯一页面标题，不增加重复大标题或整块规则提示条。

## 3. 树形表格字段

| 字段 | 展示规则 |
|---|---|
| 分类名称 | 一级分类显示展开按钮；二级分类缩进显示 |
| 分类编码 | 展示平台分类唯一编码 |
| 分类层级 | 显示“一级分类”或“二级分类” |
| 集采商品数 | 一级分类汇总全部直属二级分类，二级分类统计直属集采商品 |
| 自营商品数 | 一级分类汇总全部直属二级分类，二级分类统计直属自营商品 |
| 状态 | 启用、停用 |
| 排序 | 同层级内的排序值 |
| 更新时间 | 最近一次分类配置更新时间 |
| 操作 | 编辑、启用/停用、删除 |

不设置单独的“商品总数”列，避免与两种来源数量重复；需要总量时可由集采商品数与自营商品数相加得出。

## 4. 数量统计口径

### 4.1 二级分类

- 集采商品数：已经映射到当前二级分类的有效集采商品数量。
- 自营商品数：直接选择当前二级分类的有效自营商品数量。
- 停用或已删除商品不计入有效商品数量。

### 4.2 一级分类

- 一级分类不直接挂商品。
- 一级分类集采商品数等于其全部二级分类集采商品数之和。
- 一级分类自营商品数等于其全部二级分类自营商品数之和。
- 一级分类统计值由系统聚合，不允许人工编辑。

### 4.3 数据更新

以下事件触发数量重新统计：

- 集采分类映射建立、修改或解除。
- 集采商品启用、停用或删除。
- 自营商品新增、修改分类、启用、停用或删除。
- 二级分类迁移至其他一级分类。

原型使用静态示例数量；正式系统由查询接口返回聚合结果。

## 5. 展开与查询交互

- 默认展开第一个一级分类，其余一级分类保持收起。
- 点击一级分类行左侧箭头展开或收起直属二级分类。
- 搜索命中二级分类时，系统自动展示并展开其父级分类。
- 按一级分类筛选时显示一级分类及其全部直属二级分类。
- 按二级分类筛选时仍保留父级行作为层级上下文。

## 6. 编辑交互

### 6.1 统一新增分类

页面右上角只保留“新增分类”入口，一级分类操作栏不再展示“新增二级分类”。新增弹窗字段包括分类层级、分类名称、分类编码、所属一级分类、排序和状态。

- 默认选择“一级分类”，所属一级分类字段隐藏或禁用。
- 选择“二级分类”后，所属一级分类字段显示并变为必填，只能选择现有一级分类。
- 分类层级切换时清空不再适用的父级值，避免把一级分类错误保存为子级。
- 二级分类未选择所属一级分类时阻止保存并提示。

不保留名为“新增一级分类”但实际可新增两级分类的入口，避免按钮语义与表单能力不一致；不保留行内快捷新增，避免同一对象的创建入口分散。

### 6.2 编辑分类

分类行“编辑”打开统一编辑弹窗：

- 一级分类可编辑名称、编码、排序和状态。
- 二级分类可编辑名称、编码、所属一级分类、排序和状态。
- 编辑已有分类时分类层级只读，不允许在一级和二级之间直接转换。
- 集采商品数、自营商品数为只读统计字段，不进入编辑表单。

### 6.3 启停与删除

- 停用分类前二次确认。
- 停用一级分类时，其直属二级分类和关联商品停止进入新的下游可售结果，但不修改历史订单。
- 存在二级分类的一级分类不能删除。
- 存在集采商品或自营商品的二级分类不能删除。
- 删除只用于没有下级分类、没有商品关联的空分类。

## 7. 异常与边界

| 场景 | 页面处理 |
|---|---|
| 分类编码重复 | 阻止保存并提示重复编码 |
| 二级分类缺少父级 | 阻止保存并提示选择一级分类 |
| 一级分类直接关联商品 | 后端拒绝并提示商品必须归入二级分类 |
| 有商品的二级分类被删除 | 阻止删除并展示两类商品关联数量 |
| 有二级分类的一级分类被删除 | 阻止删除并提示先处理下级分类 |
| 数量查询失败 | 数量列显示“统计失败”，保留分类基础信息并允许重试 |
| 并发编辑导致版本变化 | 保存失败并提示刷新后重新编辑 |

## 8. 数据与接口边界

树形表格继续使用现有分类对象，建议查询结果返回：

```text
category_id
parent_id
category_level
category_name
category_code
sourcing_product_count
self_operated_product_count
status
sort_order
updated_at
version
children[]
```

商品数量为服务端聚合字段，不在分类主表中由运营手工维护。新增、编辑、启停和删除仍调用统一分类管理接口。

## 9. 原型调整范围

- 删除原分类管理页面的左侧树和右侧分类详情面板。
- 新增树形表格、展开/收起按钮、数量列及行级操作。
- 编辑按钮在原型中打开可操作的编辑弹窗。
- 页面右上角使用“新增分类”统一创建一级或二级分类。
- 一级分类行移除“新增二级分类”，只保留编辑、启停和删除。
- 不修改“分类映射”；原独立“集采商品”页面后续已按最新收拢方案迁入供货平台内的来源商品页面。
- 不修改小程序原型。

## 10. 验收标准

1. 分类管理使用单一树形表格展示两级分类。
2. 一级分类行可以展开和收起二级分类。
3. 表格分别展示集采商品数和自营商品数。
4. 一级分类数量为下属二级分类汇总值，二级分类数量为直属商品值。
5. 页面右上角只有“新增分类”入口，一级分类行不展示“新增二级分类”。
6. 新增表单可选择一级或二级；选择二级时必须选择所属一级分类。
7. 编辑已有分类时分类层级不可修改。
8. 编辑弹窗中的数量字段不可编辑。
9. 有下级分类或商品关联时不能删除分类。
10. 页面保留灰色说明词，不出现重复大标题和整块提示内容。
