# 拾马商城后台查询列表页面统一规范

- 日期：2026-08-14
- 状态：方案已确认，原型已实施
- 适用范围：后台所有“查询条件 + 数据表格”页面

## 1. 目标

统一后台查询列表页的信息层级与操作位置，减少重复标题和非查询按钮对查询流程的干扰，使运营人员在所有列表页形成一致操作习惯。

## 2. 适用页面

本规范覆盖：

- 小程序客户、商城订单、积分账户。
- API客户、API订单、资金对账。
- 分类管理、商品管理。
- 供货平台、供货平台内来源商品、分类映射。
- 用户管理、角色权限。

经营总览、小程序商城分析、API供货分析等看板与报表页面不适用本规范。

## 3. 页面区域

普通查询列表页面从上到下只保留三个区域：

1. 页面说明与业务操作区。
2. 查询表单。
3. 数据表格与分页。

商城订单和 API 订单在第 1、2 区之间插入“订单状态快捷页签”，作为订单工作队列的专用查询视图，不改变其他列表页结构。

### 3.1 页面说明与业务操作区

- 左侧保留灰色页面说明词。
- 右侧保留与业务对象相关的页面级操作，例如新建、导出、同步、批量映射、平台兜底加价。
- 页面级业务操作不进入查询表单。

### 3.2 查询表单

查询表单只允许出现：

- 文本输入框、下拉框等查询字段。
- “查询”按钮。
- “重置”按钮。

查询表单不允许出现：

- “筛选”“更多筛选”等重复查询按钮。
- “刷新”“同步”“导出”“新增”“批量设置”等业务操作。
- 分类管理的“展开全部”“收起全部”等非查询操作。

按钮顺序固定为“查询、重置”。“查询”使用主按钮，“重置”使用普通按钮。

### 3.3 数据表格

- 删除数据表格上方单独的标题、记录数、刷新按钮和其他操作整行。
- 查询表单下方直接进入表格列头。
- 分页保留在表格底部。
- 不在表格顶部重复页面名称。

## 4. 查询与重置行为

### 4.1 查询

- 按当前表单字段刷新列表数据。
- 当前原型显示查询成功反馈；正式系统调用列表查询接口。

### 4.2 重置

点击“重置”后按以下顺序执行：

1. 清空所有文本输入框。
2. 所有下拉框恢复第一个默认选项。
3. 页码恢复第 1 页。
4. 使用空查询条件重新刷新当前列表。
5. 显示“查询条件已重置，列表已刷新”反馈。

重置不是只清空表单，必须同时刷新列表。

商品管理属于带左侧分类树的特殊查询列表：重置时保留左侧当前分类，只清空商品关键字，并将商品来源恢复为“全部来源”、商品状态恢复默认值。商品来源使用普通下拉框，不使用页签。

## 5. 页面级操作迁移

移除表格顶部整行后，其中有业务价值的操作按以下规则处理：

| 原操作 | 调整方式 |
|---|---|
| 表格标题 | 删除，不迁移 |
| 记录总数 | 删除表格顶部展示，分页中的总数保留 |
| 刷新列表/刷新状态 | 删除，使用“查询”重新加载 |
| 批量设置展示 | 移至页面说明词右侧 |
| 新建、导出、同步、批量映射 | 保留在页面说明词右侧 |

## 6. 分类管理特殊规则

- 树形表格结构和行级展开按钮保留。
- “展开全部”“收起全部”从查询表单移除。
- 页面右上角使用“新增分类”统一创建一级或二级分类；行级只保留编辑、启停、删除。
- 查询表单只保留分类名称或编码、分类层级、状态、查询、重置。

## 7. 订单列表特殊规则

- 商城订单和 API 订单在灰色页面说明下方、查询表单上方展示同一组快捷页签：全部、待处理、待发货、已发货、已完成、售后/异常。
- 每个页签显示当前其他查询条件下的订单数；一笔订单按统一优先级只计入一个聚合状态。
- 查询表单不再提供与页签重复的订单状态下拉框，只保留订单号、客户/企业、商品等查询字段以及“查询”“重置”。
- 点击页签、查询或重置均回到第 1 页；查询和重置保留当前页签，点击“全部”才取消聚合状态限制。
- 快捷页签是派生查询条件，不修改订单底层并行状态。

## 8. 系统管理特殊规则

- 用户管理查询表单只包含用户姓名或账号、所属角色、状态、查询和重置；“新建用户”位于页面说明区右侧。
- 角色权限查询表单只包含角色名称、状态、查询和重置；“新建角色”位于页面说明区右侧。
- 用户和角色的编辑、启停、密码重置与菜单授权均位于对应列表行操作栏，不在查询表单或表格顶部增加操作整行。

## 9. 原型实现约束

- 所有查询表单统一增加 `data-query-form`。
- 查询按钮统一使用 `data-query-submit`。
- 重置按钮统一使用 `data-query-reset`。
- 所有列表表格不再渲染 `.table-summary`。
- `render(view)` 统一绑定重置行为，避免每个页面重复实现。
- 重置后重新调用 `render(view)`，确保表单、页码和列表恢复初始状态。

## 10. 异常与边界

| 场景 | 处理 |
|---|---|
| 没有查询字段 | 不展示空查询表单 |
| 查询请求失败 | 保留查询条件并提示失败 |
| 重置后的刷新失败 | 表单保持已重置状态，并提示刷新失败 |
| 表格无数据 | 直接在表格内容区展示空状态，不恢复表格顶部标题 |
| 页面存在批量业务操作 | 放入页面说明词右侧，不放入查询表单 |

## 11. 验收标准

1. 所有查询列表页均无表格顶部标题整行。
2. 查询表单只包含查询字段、“查询”和“重置”。
3. 所有查询表单的按钮顺序均为“查询、重置”。
4. 点击重置后输入框清空、下拉框恢复默认、页码恢复第一页并刷新列表。
5. 新建、导出、同步等业务操作仍可从页面说明区进入。
6. 分类树形表格的行级展开和编辑操作不受影响。
7. 经营看板和渠道分析报表不受影响。
8. 商城订单和 API 订单均展示六个快捷页签，且查询表单内不再出现重复的订单状态下拉框。
9. 订单查询和重置保留当前快捷页签，点击“全部”才取消聚合状态限制。
10. 用户管理和角色权限页面继续遵循统一查询表单及列表操作栏规范。
