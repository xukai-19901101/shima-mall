# 商城订单与 API 订单操作栏设计

- 日期：2026-08-15
- 状态：已实现并通过静态与浏览器回归
- 适用范围：拾马商城平台运营后台一期静态原型
- 覆盖端：Web 平台运营后台；小程序、客户 API 和供货平台接口不做改动

## 1. 业务目标

为商城订单和 API 订单列表补充行级处理入口，使运营人员无需先进入独立详情页，就能识别当前订单可执行的操作并完成发货、退款或关闭确认。

成功标准：每条订单都有操作栏；操作按钮由当前订单状态决定；高风险操作经过表单或二次确认；操作完成后列表状态与按钮立即同步变化。

## 2. 本次范围

- 两类订单列表新增“操作”列。
- 固定提供查看详情、发货、退款、关闭订单四类入口。
- 只展示当前状态允许的操作；“退款处理中”作为不可重复提交的禁用反馈保留。
- 增加共用订单详情、发货、退款和关闭订单弹窗。
- 静态原型内更新订单状态和操作按钮，刷新页面后恢复演示数据。
- 不设计、不展示、不校验菜单权限、角色权限或按钮级权限。

## 3. 动作矩阵

| 当前状态或结果 | 查看详情 | 发货 | 退款 | 关闭订单 | 说明 |
|---|---|---|---|---|---|
| 待付款 | 显示 | 不显示 | 不显示 | 显示 | 未支付订单允许关闭 |
| 待发货 | 显示 | 显示 | 显示 | 不显示 | 已形成资金记录，取消通过退款处理 |
| 已发货 | 显示 | 不显示 | 显示 | 不显示 | 不允许重复发货或直接关闭 |
| 已完成 | 显示 | 不显示 | 显示 | 不显示 | 本期不实现售后时限校验 |
| 已取消 | 显示 | 不显示 | 不显示 | 不显示 | 终态只读 |
| 退款中、售后中或退款处理中 | 显示 | 不显示 | 显示但禁用，文案为“退款处理中” | 不显示 | 防止重复发起退款 |
| 处理中或采购结果未知 | 显示 | 不显示 | 不显示 | 不显示 | 采购结果未确定时不执行资金或履约动作 |
| 采购失败或待重试 | 显示 | 不显示 | 不显示 | 显示 | 失败订单允许人工关闭 |

规则判断优先级：退款/售后处理中 > 已取消 > 采购失败/待重试 > 待付款 > 待发货 > 已发货 > 已完成 > 处理中/结果未知。优先级用于处理订单状态与采购结果同时出现时的冲突。

## 4. 列表展示

- “操作”列放在表格最右侧，并在横向滚动时保持右侧可见。
- 每行始终先显示“查看详情”，其余按钮按动作矩阵显示。
- 可执行按钮使用链接式按钮；退款和关闭订单使用风险色，禁用按钮降低透明度并禁止点击。
- 操作列不使用“更多”下拉菜单，避免常用处理动作被隐藏。
- 现有状态快捷页签、查询和分页保持不变；已取消订单只出现在“全部”视图，不错误进入“待处理”。

## 5. 操作流程

### 5.1 查看详情

点击后打开只读弹窗，展示订单号、渠道类型、企业、商品、订单金额或积分、采购成本、订单状态和采购结果。关闭弹窗不改变订单。

### 5.2 发货

1. 仅待发货订单显示入口。
2. 弹窗展示订单号和商品，要求填写物流公司与物流单号。
3. 任一字段为空时不提交，并在弹窗内提示缺失字段。
4. 确认后当前订单状态改为“已发货”，操作栏移除发货按钮并保留查看详情、退款。

### 5.3 退款

1. 待发货、已发货和已完成订单显示入口。
2. 弹窗展示订单号、退款范围、退款原因和原路退回说明。
3. 退款原因必填；确认前必须勾选二次确认。
4. 商城订单文案为“按原积分及支付路径退回”；API 订单文案为“按原人民币结算路径退回”。
5. 确认后订单状态改为“退款中”，采购结果改为“退款处理中”；操作栏仅保留查看详情和禁用的“退款处理中”。

### 5.4 关闭订单

1. 仅待付款、采购失败或待重试订单显示入口。
2. 弹窗要求选择关闭原因并勾选二次确认。
3. 确认后订单状态改为“已取消”，采购结果改为“已关闭”；操作栏仅保留查看详情。

## 6. 数据与状态边界

- 列表现有“订单状态”和“采购结果”是静态原型展示字段；退款后分别展示“退款中”和“退款处理中”。真实系统仍需独立保存履约、支付与售后状态，本次不扩展后台数据模型。
- 静态原型只模拟当前页面内的状态变化，不声称调用真实发货、退款或关闭接口。
- 退款必须表达原路径退回，不提供切换退款渠道的入口。
- 点击查询、重置或状态页签后，使用当前内存中的演示状态重新渲染；浏览器刷新后恢复初始数据。
- 重复点击、弹窗关闭或校验失败不得改变订单状态。

## 7. 异常场景

| 场景 | 处理方式 |
|---|---|
| 发货物流公司为空 | 弹窗内提示“请选择物流公司” |
| 发货物流单号为空 | 弹窗内提示“请输入物流单号” |
| 退款原因为空 | 弹窗内提示“请填写退款原因” |
| 退款未二次确认 | 弹窗内提示“请确认退款影响” |
| 关闭原因未选择 | 弹窗内提示“请选择关闭原因” |
| 关闭未二次确认 | 弹窗内提示“请确认关闭订单” |
| 退款处理中再次点击 | 按钮禁用，不打开弹窗 |
| 当前查询条件下操作后不再匹配 | 订单从当前快捷视图移除，计数同步重算 |

## 8. 验收标准

- 商城订单和 API 订单表格都增加最右侧“操作”列，每条订单始终有“查看详情”。
- 待发货示例展示发货和退款；已发货及已完成示例展示退款；退款处理中示例展示禁用按钮；采购失败示例展示关闭订单。
- 发货、退款和关闭订单均经过表单校验或二次确认。
- 操作成功后状态、采购结果、快捷页签计数及操作按钮同步刷新。
- 已取消订单不进入“待处理”快捷页签。
- 订单详情、查询、重置、快捷页签和分页原流程不受影响。
- 1440px 与 1024px 下操作列保持可用，页面不产生新增的页面级横向滚动。
- 系统角色页面不新增订单按钮权限配置。
- PRD、静态合约测试和浏览器测试同步更新。

## 9. 不在本次范围

- 角色权限、菜单权限、按钮级权限或审批流。
- 真实物流、退款、支付或订单关闭接口。
- 部分退款、多次退款、退款失败重试或售后时限计算。
- 批量发货、批量退款或批量关闭。
- 新增订单详情独立页面。
