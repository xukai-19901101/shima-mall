# 集采商品收拢至商品管理设计

- 日期：2026-08-14
- 状态：方案已确认，原型与 PRD 已实施
- 适用范围：拾马商城平台后台一期

## 1. 业务目标

减少运营人员在“商品管理”和“集采商品”之间切换的成本，将已经进入平台商品库的自营商品与集采商品统一放在“商品管理”中查看和维护。

本次只调整菜单、页面入口和查询方式，不梳理或新增企业级、分类级、商品级投放开关。商品投放规则将在后续独立需求中统一设计。

## 2. 核心边界

- 商品管理只展示已经进入平台商品库的商品。
- 自营商品创建后直接进入平台商品库。
- 集采来源商品完成必要的分类映射并进入平台商品库后，才出现在商品管理。
- 未映射、未归集的上游原始商品不进入商品管理。
- 上游原始商品仍独立保存在来源商品数据结构中，不与平台商品表合并。
- 本次不新增商品展示开关，也不调整现有投放规则的计算逻辑。

## 3. 菜单调整

调整后菜单：

```text
商品库
├── 分类管理
└── 商品管理

供货平台管理
├── 供货平台
└── 分类映射
```

删除“供货平台管理 / 集采商品”独立菜单。

“供货平台管理”继续负责上游平台接入、同步状态和分类映射，不承担平台商品的日常运营管理。

## 4. 商品管理页面

### 4.1 页面结构

继续沿用现有主从布局：

- 左侧：平台两级分类树，默认选中“全部”。
- 右侧顶部：当前分类、查询字段、查询、重置。
- 右侧下方：统一商品列表与分页。

不增加“平台商品”“集采来源商品”等页签。

### 4.2 查询条件

在现有查询表单中增加普通下拉字段“商品来源”：

- 全部来源。
- 自营商品。
- 集采商品。

查询条件与分类树共同生效：

```text
分类范围 AND 商品关键字 AND 商品来源 AND 商品状态
```

点击重置时：

- 清空商品关键字。
- 商品来源恢复“全部来源”。
- 商品状态恢复默认值。
- 保留当前左侧分类。
- 页码回到第 1 页并刷新列表。

### 4.3 列表字段

统一列表字段：

| 字段 | 自营商品 | 集采商品 |
|---|---|---|
| 商品编码 | 平台商品编码 | 平台商品编码 |
| 商品名称 | 平台维护 | 来源同步后形成平台商品 |
| 平台分类 | 自营上架时选择 | 来源分类映射后归入 |
| 商品来源 | 自营 | 集采 |
| 来源平台 | 平台自营 | 对应供货平台 |
| SKU数 | 平台维护 | 来源同步 |
| 成本价/采购价 | 平台维护 | 上游最新采购价 |
| 可售库存 | 平台维护 | 上游最新库存 |
| 状态 | 平台商品状态 | 平台商品状态与同步结果 |
| 操作 | 编辑、查看SKU、成本、库存、上下架 | 查看详情、查看SKU、同步信息、上下架 |

集采商品的成本和库存只读，不允许平台运营手工覆盖；自营商品的成本和库存继续可编辑。

## 5. 来源商品承接位置

原“集采商品”页面中的上游原始数据移入“供货平台详情 / 来源商品”页签。

来源商品页签展示：

- 来源商品编码。
- 来源商品名称。
- 来源分类和来源 SKU。
- 最新采购价和库存。
- 分类映射结果。
- 平台商品归集状态。
- 最近同步时间和同步结果。

来源商品页签支持：查看详情、重新同步、查看映射结果。分类映射的建立、修改和解除仍统一进入“分类映射”菜单处理，避免在两个入口重复配置。

## 6. 数据流转

```text
供货平台同步来源商品
→ 保存或更新来源商品、SKU、采购价、库存
→ 来源分类完成平台分类映射
→ 来源商品满足归集条件
→ 创建或关联平台 SPU/SKU
→ 商品管理统一展示
```

同步后的字段职责：

- 来源商品表保存上游原始值和同步状态。
- 平台商品表保存平台商品编码、平台分类、商品状态和来源关联。
- 集采商品的成本、库存从来源 SKU 最新成功同步结果派生。
- 自营商品不存在来源商品记录，由平台直接维护。

## 7. 归集条件

集采来源商品进入商品管理至少满足：

1. 来源商品和来源 SKU 有效。
2. 来源分类已唯一映射到平台二级分类。
3. 已创建或关联平台商品。
4. 最近一次基础信息同步成功，或存在可使用的最近成功数据。

库存为零不阻止商品进入平台商品库，但会影响其可售状态。同步异常商品可继续显示在商品管理中，并明确标记同步异常或数据已过期。

## 8. 投放开关边界

本次不新增、不迁移、不合并以下投放配置：

- 企业开放分类。
- 企业相关商品范围配置。
- 分类级投放配置。
- 商品级展示配置。
- 供货平台渠道总开关。

商品管理本次不增加“小程序展示”“API展示”开关。旧集采商品页面中的商品级开关不迁移到统一商品列表，其现有配置数据保留，等待后续“商品投放统一设置”需求确定迁移和生效规则。

在后续规则确认前，本次页面调整不得改变线上已有商品的实际可见性结果。

## 9. 菜单权限迁移

系统角色权限中的 `sourcing-products` 菜单权限随菜单删除而失效。

迁移规则：

- 原拥有“集采商品”权限且没有“商品管理”权限的角色，自动增加“商品管理”权限。
- 原已拥有“商品管理”权限的角色保持不变。
- 删除所有角色与 `sourcing-products` 的菜单关联。
- “供货运营”等原集采商品使用者迁移后可查看商品管理中的全部自营和集采商品。

一期只有菜单权限，不按商品来源限制数据范围，也不增加只读角色或按钮权限。

## 10. 路由与存量处理

- 侧边导航删除“集采商品”。
- 旧集采商品菜单地址访问时，跳转到“商品管理”，并将商品来源查询条件预设为“集采商品”。
- 供货平台详情中的来源商品链接进入对应平台的来源商品页签。
- 不删除来源商品、来源 SKU、同步记录或历史投放配置数据。
- 不修改历史订单中保存的商品来源和成本快照。

## 11. 异常与边界

| 场景 | 处理 |
|---|---|
| 来源分类未映射 | 不进入商品管理，在供货平台详情中标记待映射 |
| 来源商品已同步但未关联平台商品 | 不进入商品管理，标记待归集 |
| 已归集商品后续同步失败 | 继续展示最近成功数据并标记同步异常 |
| 集采商品库存为零 | 继续展示，标记无货，不允许新下单 |
| 集采成本或库存尝试手工修改 | 拒绝并提示由供货平台同步 |
| 删除旧菜单后访问旧地址 | 跳转商品管理并预设集采来源筛选 |
| 角色仅拥有旧集采商品权限 | 自动迁移为商品管理权限 |
| 商品来源筛选与分类无结果 | 列表显示空状态，保留当前查询条件 |

## 12. 验收标准

1. “供货平台管理”下不再展示“集采商品”菜单。
2. 商品管理只有一个列表，不增加来源类型页签。
3. 商品管理查询表单包含全部来源、自营商品、集采商品下拉选项。
4. 自营和已归集集采商品可在同一列表中按来源筛选。
5. 未映射或未归集来源商品不进入商品管理。
6. 上游原始商品可从供货平台详情的来源商品页签查看。
7. 自营成本和库存可编辑，集采成本和库存只读。
8. 本次页面中不新增小程序或 API 商品展示开关。
9. 原集采商品权限迁移为商品管理权限，旧权限关联被清理。
10. 旧集采商品地址跳转商品管理并预设集采来源筛选。
11. 存量来源商品、同步记录、投放配置和历史订单数据不被删除或改写。
