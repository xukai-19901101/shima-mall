# 拾马商城后台一期 PRD

- 版本：V1.0
- 日期：2026-08-14
- 状态：已确认，进入原型实施

## 1. 产品目标

拾马商城面向两类互斥的企业客户：小程序商城客户与 API 供货客户。平台运营人员需要在同一后台中分别管理两种渠道，但企业、商品、订单、定价、账户和结算仍共用同一套底层业务逻辑与数据结构。

一期目标：

1. 运营人员能从菜单和页面上下文快速识别当前管理渠道。
2. 企业创建时固定渠道，创建后不允许切换。
3. 商品库与供货平台按业务对象收拢，不将字段维护动作机械拆成菜单。
4. 经营看板能够分别分析小程序与 API 两种销售渠道。
5. 小程序积分资金、API 订单采购与供应链余额形成可统计、可校对的最小闭环。
6. 平台内部人员使用独立后台账号，并通过角色控制可见和可访问的菜单。

## 2. 核心业务约束

- `channel_type` 只能是 `MINIAPP` 或 `API`。
- 企业渠道在创建入口确定，创建后永久不可修改。
- 同一企业主体不能跨渠道重复创建。
- 小程序渠道使用积分账户，支持预付或后结。
- API 渠道不使用积分，按人民币余额、授信或账期结算。
- 商品只维护成本价/采购价，不维护固定售价字段。
- 集采成本取上游最新采购价，自营成本由平台维护。
- 平台使用统一两级商品分类；上游两级分类映射到平台分类。
- 系统管理只面向平台内部后台账号，不包含小程序客户、API 客户或终端用户账号。
- 后台用户采用单用户单角色；一期只实现菜单权限，不实现按钮权限或数据范围权限。

菜单设计规则：

- 菜单对应稳定业务对象或跨对象高频工作队列。
- 自营商品上架是商品管理的创建动作，不单独设菜单。
- 成本和库存是 SKU 属性，收拢到商品管理列表和详情。
- API 接入、同步状态和渠道总开关收拢到供货平台详情。
- 上游原始商品作为供货平台内部的“来源商品”页面，不单独设置侧边菜单。
- 商品投放开关暂不调整，后续另行统一梳理企业、分类和商品维度的投放规则。
- 分类映射需要按供货平台集中查看来源二级分类、维护单条映射和执行增量导入，因此保留独立菜单。
- 平台内部账号和菜单授权分别收拢到用户管理、角色权限，不与客户账号混用。

### 3.1 查询列表页面统一规范

所有“查询条件 + 数据表格”页面统一按以下三段结构展示：页面说明与业务操作、查询表单、数据表格与分页。

- 页面左侧保留灰色说明词；新建、导出、同步、导入等业务操作放在说明区右侧。
- 查询表单只包含查询字段、“查询”和“重置”，按钮顺序固定为“查询、重置”。
- 查询表单不展示“筛选”“更多筛选”、刷新、同步、导出、新增、批量操作或展开全部等非查询按钮。
- 数据表格上方不再展示重复的表格标题、记录数、刷新按钮或其他操作整行，查询表单下方直接显示表格列头。
- 分页中的记录总数保留。
- 点击“重置”后清空输入框、恢复下拉框默认选项、页码回到第 1 页，并使用空条件刷新当前列表。
- 商城订单和 API 订单在页面说明区与查询表单之间增加聚合状态快捷页签；页签属于订单工作队列，不在查询表单中重复提供订单状态下拉框。

本规范不适用于经营总览和渠道经营分析等看板与报表页面。

## 4. 经营看板

### 4.1 经营总览

展示跨渠道汇总指标：有效订单、企业结算额、采购成本、毛利、待回款、商品数量和待处理事项。渠道交易趋势分别展示小程序和 API，不提供跨渠道业务操作入口。

### 4.2 渠道经营分析

页面顶部使用“小程序商城客户”与“API 供货客户”两个 Tab。切换 Tab 时，核心指标、订单与资金结算闭环、商品销量排行、企业贡献排行和导出口径同步切换。页面不提供“全部渠道” Tab，跨渠道汇总仍属于“经营总览”。

#### 4.2.1 小程序商城客户口径

##### 订单与资金结算闭环

核心指标：有效订单、消费积分、企业结算金额、采购成本、毛利、冻结积分、预付资金余额、后结应收。

双轨图节点：

```text
订单流：提交订单 → 采购成功 → 履约完成 → 订单完成
资金流：积分冻结 → 积分扣减/采购支出 → 企业结算出账 → 预付入账/后结待回款
```

##### 商品销量排行

字段：商品、来源、销量、订单数、消费积分、结算金额、采购成本、毛利额、毛利率、售后率。

支持按销量、结算金额和毛利额切换排序。

##### 企业贡献排行

字段：企业、结算方式、订单数、消费积分、结算金额、采购成本、毛利、贡献占比、待回款。

#### 4.2.2 API 供货客户口径

不展示积分字段。

##### 订单与资金结算闭环

核心指标：有效订单、订单结算额、采购成本、毛利、采购成功率、结果未知订单、客户待回款、上游余额差异。

双轨图节点：

```text
订单流：API 订单受理 → 上游采购成功 → 履约完成 → 订单完成
资金流：余额/授信占用 → 上游采购支出 → 客户结算出账 → 客户回款/上游余额校对
```

##### 商品销量排行

字段：商品、供货平台、销量、订单数、结算金额、采购成本、毛利、采购成功率、售后率。

##### 企业贡献排行

字段：企业、结算方式、订单数、结算金额、采购成本、毛利、贡献占比、待回款、回款率、接口成功率。

### 4.3 报表公共规则

- 支持今天、本周、本月和自定义时间。
- 支持企业、商品分类、供货平台和结算方式筛选。
- 排行与金额仅统计有效订单。
- 取消订单不计入销量和结算额。
- 退款按退款确认时间冲减。
- 结算金额使用订单价格快照。
- 采购成本使用订单实际采购成本。
- 毛利额＝企业结算金额－采购成本－退款调整。
- 企业贡献占比＝企业结算金额÷对应渠道结算总额。
- 两个客户类型 Tab 在相同时间范围内的合计必须与经营总览一致。

## 5. 小程序商城客户

### 5.1 小程序客户

列表字段：企业编码、企业名称、结算方式、可用积分、冻结积分、开放分类、订单数、状态。

操作：新建小程序客户、查看详情、启用、停用。创建入口固定 `channel_type=MINIAPP`。

详情收拢：基本信息、商品范围与定价、积分与结算、订单记录、操作记录。

### 5.2 商城订单

仅展示小程序订单。核心字段：订单号、企业、商品、消费积分、结算金额、采购成本、积分状态、采购状态、履约状态和售后状态。

- 快捷页签固定为：全部、待处理、待发货、已发货、已完成、售后/异常，并显示各视图订单数。
- 聚合优先级为：售后/异常 > 待处理 > 待发货 > 已发货 > 已完成，一笔订单只进入一个状态视图。
- 查询和重置保留当前页签，页签切换、查询和重置均回到第 1 页；点击“全部”才取消聚合状态限制。
- 快捷页签仅为查询派生视图，不写回订单，也不替代积分、采购、履约和售后等底层并行状态。
- 列表最右侧增加操作列，每条订单固定提供查看详情；待发货显示发货、退款，已发货和已完成显示退款，退款或售后处理中显示禁用的“退款处理中”，待付款显示关闭订单。
- 发货要求填写物流公司和物流单号；退款要求填写原因并二次确认，明确按原积分及支付路径退回；关闭订单要求选择原因并二次确认。
- 操作成功后静态原型同步刷新订单展示状态、操作按钮和快捷页签计数；已取消订单只进入“全部”视图。
- 本期只增加功能按钮和操作弹窗，不增加角色、菜单或按钮权限设计。

### 5.3 积分对账

展示可用积分、冻结积分、累计发行、累计消费、预付资金余额、后结应收、信用额度和账户流水；保留企业账户查询、登记积分充值和分页流程。

- 页面说明与查询表单之间增加关键 KPI 看板，固定展示：本月积分充值、本月积分消费、当前可用积分、当前冻结积分、本月累计差异、待核对订单。
- 本月积分充值、本月积分消费和本月累计差异按当前自然月累计；当前可用积分和当前冻结积分展示当前账户汇总快照，待核对订单统计尚未完成冻结、扣减或退回归因的订单。
- 积分差异来源为订单应冻结、应扣减或应退回积分与账户流水实际结果不一致；同一未解决差异重复核对时只累计一次。
- 跨月未解决订单继续计入待核对订单；缺失的积分快照不得按零计入，无业务与数据缺失必须分别展示为 `0 积分` 和“暂未获取”。
- 查询表单只筛选下方企业账户明细，不改变顶部全局 KPI；KPI 卡片一期只读，不增加下钻、趋势或筛选联动。
- 1440px 下六项 KPI 单行展示，1024px 下每行三项且不得产生页面级横向滚动。
- 内部视图代码继续使用 `points-accounts`；本次只同步展示名称和对账功能，不增加或调整权限逻辑。

## 6. API供货客户

### 6.1 API客户

列表字段：客户编码、企业名称、鉴权状态、结算方式、余额/授信、已占用额度、最近调用时间、状态。

操作：新建 API 客户、查看详情、启用、停用。创建入口固定 `channel_type=API`。

详情收拢：基本信息、商品范围与定价、API接入、资金结算、订单记录、操作记录。

### 6.2 API订单

仅展示 API 订单。核心字段：客户订单号、平台订单号、企业、商品、结算金额、采购成本、接口受理状态、采购状态、履约状态和售后状态。

- 快捷页签固定为：全部、待处理、待发货、已发货、已完成、售后/异常，并显示各视图订单数。
- 聚合优先级为：售后/异常 > 待处理 > 待发货 > 已发货 > 已完成；接口已受理但采购结果未知进入“待处理”，采购失败或待重试进入“售后/异常”。
- 查询和重置保留当前页签，页签切换、查询和重置均回到第 1 页；点击“全部”才取消聚合状态限制。
- 快捷页签仅为查询派生视图，不写回订单，也不替代接口受理、采购、履约和售后等底层并行状态。
- 列表最右侧增加操作列，每条订单固定提供查看详情；待发货显示发货、退款，已发货和已完成显示退款，退款或售后处理中显示禁用的“退款处理中”，采购失败或待重试显示关闭订单。
- 发货要求填写物流公司和物流单号；退款要求填写原因并二次确认，明确按原人民币结算路径退回；关闭订单要求选择原因并二次确认。
- 操作成功后静态原型同步刷新订单展示状态、操作按钮和快捷页签计数；已取消订单只进入“全部”视图。
- 本期只增加功能按钮和操作弹窗，不增加角色、菜单或按钮权限设计。

### 6.3 资金对账

展示订单统计金额、上游采购金额、理论余额、余额接口实际值、差异金额、查询时间和校对结果。

理论余额＝期初余额＋充值－成功采购成本＋退款与调整。

- 页面说明与查询表单之间增加关键 KPI 看板，固定展示：本月采购金额、本月退款与调整、当前接口余额、当前账面余额、本月累计差异、待核对订单。
- 本月采购金额、本月退款与调整、本月累计差异按当前自然月累计；接口余额和账面余额展示最近一次校对快照，待核对订单统计当前仍未闭环的订单。
- 同一未解决差异在重复校对中只累计一次；部分平台余额查询失败时，只汇总成功返回的平台并明确已更新平台数，不将缺失余额按零计入。
- 查询表单只筛选下方对账记录，不改变顶部全局 KPI；KPI 卡片一期只读，不增加下钻或筛选联动。
- 1440px 下六项 KPI 单行展示，1024px 下每行三项且不得产生页面级横向滚动。

## 7. 商品库

### 7.1 分类管理

- 使用可展开的树形表格维护平台统一两级分类，一级分类作为父行，展开后显示直属二级分类。
- 列表字段：分类名称、分类编码、分类层级、集采商品数、自营商品数、状态、排序、更新时间、操作。
- 一级分类的集采商品数和自营商品数分别汇总其全部二级分类；二级分类只统计直接归入本分类的有效商品。
- 支持分类名称或编码搜索、层级筛选和状态筛选；一级分类通过行内箭头展开或收起。
- 页面右上角使用“新增分类”统一创建一级或二级分类；新增时默认一级，选择二级后必须选择所属一级分类。
- 一级分类操作栏不设置“新增二级分类”；所有分类行只保留编辑、启停和删除，编辑时分类层级不可修改。
- 一级分类存在二级分类时禁止删除；二级分类存在集采商品或自营商品时禁止删除。
- 自营商品直接选择平台二级分类；上游分类映射仍在“供货平台管理 / 分类映射”操作。

### 7.2 商品管理

商品管理以平台标准 SPU/SKU 为对象，使用单一列表统一展示自营商品和已经归集进入平台商品库的集采商品；未映射、未归集的上游原始商品不进入本页面。

- 页面采用左侧分类树、右侧商品列表的主从布局；左侧固定“全部”节点并默认选中。
- 选择一级分类时查询该一级分类及其全部二级分类商品；选择二级分类时仅查询二级分类直属商品。
- 右侧查询区同步展示当前分类，并提供商品关键字、商品来源、商品状态查询；商品来源使用普通下拉框，不设置来源页签。
- 商品来源选项固定为全部来源、自营商品、集采商品；各条件与左侧分类范围同时生效。
- 分类切换、查询和重置后页码回到第 1 页；重置清空关键字、恢复全部来源和默认状态，但保留当前分类选择。

列表字段：商品编码、商品名称、平台分类、SKU数、商品来源、来源平台、成本价/采购价、库存、状态和操作。

页面操作：新建自营商品、平台兜底加价配置和导出。

行操作：自营商品提供编辑、查看SKU和上下架；集采商品提供查看详情、查看SKU、同步信息和上下架。

详情页签：基本信息、SKU与规格、成本、库存、销售状态。

- 自营成本和库存可维护。
- 集采成本和库存来自上游同步，平台只读。
- 售价、企业结算价和积分动态计算，不保存固定售价。
- 本次不在商品管理增加小程序展示或 API 展示开关，也不改变存量投放配置的实际生效逻辑。

## 8. 供货平台管理

### 8.1 供货平台

列表字段：平台名称、连接状态、鉴权状态、最近同步时间、分类数、商品数和异常数。

详情页签：基本信息、接入配置、同步状态、来源商品、渠道展示、接口日志。

渠道展示包含“小程序商城”和“API供货”两个总开关。关闭后停止对应渠道的新展示和新下单，不影响历史订单履约。

“来源商品”从供货平台列表行内进入，只展示当前供货平台的上游原始分类、商品和 SKU 数据。字段包括来源商品编码、商品名称、来源分类、来源SKU、最新采购价、库存、分类映射、平台商品归集状态、最近同步和同步结果；操作只包含查看详情、重新同步和查看映射。该页面不提供小程序或 API 商品展示开关。

### 8.2 分类映射

分类映射只处理“来源二级分类 → 平台二级分类”的当前关联关系。来源一级分类只用于路径展示，不参与映射；自营商品直接选择平台二级分类，不经过本页面。

页面采用“供货平台页签 + 查询表单 + 左右树形对照区”的结构。不同供货平台分别切换、分别导入，不提供跨平台统一操作。查询字段包括来源分类关键字、映射状态和来源状态；映射状态只包含未映射、已映射，来源失效作为独立来源状态展示。

左侧展示与商品管理一致的平台两级分类树，但不显示“全部”节点；右侧展示当前供货平台自身的来源两级分类树。来源一级分类只用于分组，来源二级分类才参与映射。映射关系从右侧来源二级分类指向左侧平台二级分类，关系线中部显示该来源分类的有效商品数量；当前查询条件未命中的来源分类及关系不展示。

来源二级分类节点展示来源分类编码、来源分类路径、有效商品数、映射状态、来源状态、更新时间和操作。有效商品数可点击进入当前供货平台的来源商品页，并自动带入来源分类和归集状态条件。映射页不展示商品明细、商品图片或缩略图。

单条操作：设置映射、修改映射、解除映射和查看历史。设置或修改时只允许选择启用中的平台二级分类；解除映射不受有效商品数量限制，但必须二次确认。解除后相关商品立即退出商品管理和下游新展示、新下单范围，并进入来源商品“待映射”视图；重新映射后自动恢复归集，不修改商品表中的来源分类数据。

导入仅用于当前供货平台的增量调整，每行明确填写“绑定”或“解除”。未出现在文件中的关系保持不变；文件中的供货平台编码必须与当前页签一致；同一来源分类在同一文件重复出现时相关行全部失败，不采用最后一行覆盖。执行流程为上传文件、预览校验、人工确认、执行；允许部分成功，失败行可下载。预览结果绑定当前平台的映射版本，确认前版本发生变化时必须重新预览。

映射规则：

- 同一供货平台的一个来源二级分类最多映射到一个平台二级分类。
- 一个平台二级分类可以接收同一或不同供货平台的多个来源二级分类。
- 映射保存、解除和导入都执行唯一性与版本校验，不保存“冲突”业务状态。
- 来源分类失效或删除时保留映射关系用于审计，但该关系不再参与分类解析；相同来源分类 ID 恢复后映射自动重新生效。
- 平台目标分类停用时保留关系，但对应商品停止进入下游可售范围；目标分类存在映射关系时禁止删除，并提供关联映射查询入口。

集采商品只保存供货平台和来源分类 ID，平台分类通过最新有效映射动态解析。修改映射只更新映射关系、行版本和供货平台映射版本，用于驱动商品管理、企业开放分类和分类加价规则刷新，不迁移或批量更新商品表；历史订单保留下单时的分类与价格快照。

每次手工设置、修改、解除、来源恢复和导入任务均记录审计历史，包括变更前后分类、操作来源、操作人、时间、版本和受影响商品数。页面提供当前供货平台的导入记录和单条关系历史。

## 9. 系统管理

### 9.1 用户管理

仅管理拾马商城平台内部后台账号，与小程序客户、API 客户账号完全隔离。

- 查询字段：用户姓名、登录账号、所属角色、状态。
- 列表字段：用户姓名、登录账号、手机号、所属角色、状态、最后登录时间、创建时间和操作。
- 操作：新建、编辑、启用、停用、重置密码和分配一个角色。
- 登录账号全局唯一且创建后不可修改；停用用户后禁止登录并使已有会话失效。
- 不提供用户硬删除，避免历史操作记录失去责任主体。
- 最后一个启用中的超级管理员用户不可停用，也不可改为其他角色。

### 9.2 角色权限

- 查询字段：角色名称、状态。
- 列表字段：角色名称、角色说明、关联用户数、已授权菜单数、状态、更新时间和操作。
- 操作：新建、编辑、启用、停用和配置菜单权限。
- 菜单权限树按一级模块和二级菜单展示；父子节点联动，普通角色至少选择一个二级菜单。
- 用户只能绑定一个启用中的角色；角色停用后，关联用户禁止登录且已有会话失效。
- 系统内置“超级管理员”，自动拥有全部当前及未来菜单，不允许停用、删除或减少菜单权限。
- 前端隐藏未授权菜单，后端仍须校验页面访问权限；直接访问未授权页面时返回无权限结果。
- 一期不实现按钮权限、数据范围权限、多角色、部门、岗位和组织架构。
- 删除旧 `sourcing-products` 菜单权限时，原仅拥有该权限的角色自动增加 `products` 商品管理权限，并清理旧菜单关联；一期不按商品来源增加数据范围或按钮权限。

旧集采商品地址访问时跳转到商品管理，并将商品来源预设为“集采商品”。来源商品、来源SKU、同步记录、历史投放配置和历史订单商品快照均保留，不因菜单调整而删除或改写。

### 9.3 API文档

系统管理提供统一 API 文档入口，只承担查看当前文档版本、预览公开页面和复制公开链接，不提供文档编辑器、分享记录或客户专属配置。

- 所有 API 客户访问同一套标准文档。
- 公开链接长期有效，无需后台账号、访问密码、有效期或客户鉴权。
- 后台展示公开地址、当前版本、最近更新时间、公开状态和十个章节目录概览。
- 外部页面独立于后台壳层，支持目录定位、关键字搜索、代码复制和移动端目录抽屉。
- 外部页面包含接入鉴权、商品与SKU、地址库存运费、创建订单、订单查询、物流、取消异常、账户余额、回调幂等、错误码与联调示例十个章节。
- 页面不展示客户信息或任何真实 AppKey、Secret、Token；原型接口路径和示例不代表生产接口已经发布。

## 10. 数据与逻辑复用

- 企业、商品策略、标准商品、来源商品、分类映射、订单、账户、流水和账单继续使用统一数据结构。
- 企业和订单保存单值 `channel_type`。
- 页面使用固定渠道路由，后端仍校验数据所属渠道。
- 两个客户模块共用企业、商品定价、订单、采购、账户和结算服务。
- 小程序和 API 的差异通过渠道策略实现，不复制核心服务。

## 11. 异常与边界

| 场景 | 处理 |
|---|---|
| 修改企业渠道 | 拒绝并返回 `CHANNEL_TYPE_IMMUTABLE` |
| 同一企业跨渠道重复创建 | 返回 `ENTERPRISE_CHANNEL_CONFLICT` |
| 错误渠道访问客户 | 拒绝展示和操作 |
| 分类未映射 | 商品不进入下游可售池 |
| 上游成本/库存同步失败 | 保留最近成功值并标记过期 |
| 供货平台渠道总开关关闭 | 停止新展示和下单，历史订单继续履约 |
| 余额查询失败 | 记录失败，不生成已校对结论 |
| 登录账号或角色名称重复 | 阻止保存并提示已存在 |
| 用户绑定停用角色 | 阻止保存 |
| 普通角色未配置二级菜单 | 阻止保存 |
| 停用最后一个超级管理员 | 阻止操作 |
| 访问未授权后台页面 | 返回无权限并跳转至首个有权菜单 |

## 12. 一期范围外

- B端客户自助后台。
- 渠道切换或历史订单迁移。
- 供应商自助上架和发货后台。
- 后台按钮权限、数据范围权限、单用户多角色和组织架构。
- 拆分两套企业、商品、订单或结算服务。

## 13. 验收标准

1. 菜单与本 PRD 第3节完全一致。
2. 小程序与 API 客户、订单、账户入口完全拆分。
3. 渠道经营分析页通过小程序商城客户与 API 供货客户 Tab 切换口径，两个 Tab 均包含订单资金双轨图、商品排行和企业贡献排行。
4. 商品库只包含分类管理和商品管理。
5. 自营上架、成本和库存收拢到商品管理。
6. 供货平台管理侧边菜单只包含供货平台和分类映射；上游原始商品从供货平台行内进入来源商品页。
7. API接入和渠道总开关收拢到供货平台详情。
8. 商品管理使用商品来源下拉筛选自营和已归集集采商品，不使用来源页签，且不出现未映射或未归集来源商品。
9. 企业渠道不可修改，不存在“小程序 + API”组合数据。
10. 页面保留左上角灰色说明词，不出现重复大标题和整块规则提示条。
11. 侧边导航包含系统管理、用户管理和角色权限。
12. 后台用户可新建、编辑、启停、重置密码并分配单个角色。
13. 角色可配置菜单权限，用户登录后只显示且只能访问已授权菜单。
14. 超级管理员始终拥有全部菜单且不可停用或减少权限。
15. 一期界面中不出现按钮权限、数据范围权限、多角色或组织架构配置。
16. 商品管理与来源商品页均不新增小程序或 API 商品展示开关。
17. 旧集采商品菜单权限迁移为商品管理权限，旧地址跳转商品管理并预设集采来源。
18. 分类映射仅处理来源二级分类，并按供货平台页签分别展示和导入；页面不出现来源一级分类映射、待确认、冲突状态、页面多选或批量映射按钮。
19. 单条映射、修改、解除、历史查看和增量导入均可形成操作闭环，解除后相关商品可在来源商品“待映射”视图定位。
20. 集采商品的平台分类由映射动态解析，映射变更不迁移商品表，历史订单分类和价格快照不受影响。
21. 系统管理包含 API文档菜单，角色菜单权限树同步出现该菜单。
22. 后台 API文档页只提供版本、公开地址、目录概览、预览和复制链接，不出现分享密码、有效期、停用或分享记录。
23. 外部 API 文档无需登录即可长期访问，并完整展示十个已确认章节，不复用后台导航或泄露真实客户凭证。
